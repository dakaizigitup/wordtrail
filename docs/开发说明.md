# 开发说明

## 0.1.2 自适应界面

Android 在实际 InputView 测量时确定可用宽度，键区最多 1000dp 居中，宽屏/普通手机/较矮窗口分别采用 52/46/38dp 键高。顶部工具保持固定尺寸，拼音和页码并入工具栏，底部常驻中/英。按键行关闭文字基线对齐，统一按按钮中心对齐；独立 Drawable 图标在按钮中心绘制，不使用靠左的 compound drawable。

候选在手机/宽屏分别固定 118/142dp 宽、72dp 高，读音数量不参与卡片尺寸。点详情按钮或下滑候选可打开 28dp 标题与最多 80dp 的 ScrollView，显示完整释义及第一英文译词的全部 UK/US 变体。新输入、换页或换语言关闭旧详情，不重新应用上屏文本。空闲和组句期间保持相同键位，避免快速输入时因候选出现而移动按键。

iOS 源码使用同样的宽度上限、固定候选和底部切换，标准 SF Symbols 与居中按钮取代字符图标；根据可见详情调整键盘高度，仍未在 Xcode 编译或实测。

## 架构

按键 → 平台队列 → JSON 会话 → 青简 Engine → 候选快照 → 平台界面 → 系统输入连接。

Rust 引擎不导入平台界面 API。候选带 revision，点选时验证该版本，防止键入新字符后误选旧候选。平台使用串行队列避免并发修改引擎，用 epoch 丢弃输入框切换前的界面响应。核心支持 create/key/select/translation/space/enter/backspace/toggle/reset/language/next_page/previous_page/state/flush/destroy。

Android 在普通文本框使用 setComposingText；iOS 把未完成拼音显示在键盘候选区，选词后才通过 textDocumentProxy 上屏。两种平台实现不同，需分别验证宿主兼容性。

词频和译词熟悉度保存于应用/扩展私有目录。没有网络接口、原始输入日志、云同步或第三方分析 SDK。Android 定时保存及退出保存；iOS 隐藏键盘时保存。只加载当前学习语言的 glossary，不包含桌面神经模型和整句统计模型。

## 本机 Windows Android 构建

工具链位于 `D:\soft\英语输入法\mobile-toolchain`，不修改全局 PATH。配置文件 `toolchain.json` 提供 java_home/sdk_root/ndk_version/rustup_home/cargo_home。

- Rust 1.96.0，Windows GNU 主工具链，Android aarch64 和 x86_64 target。
- JDK 21、Android Platform 35、Build-Tools 35.0.0、NDK 28.2.13676358。
- 本机 host-link.cmd 和 LLVM MinGW 只用于 Windows 主机上的 Rust 构建脚本；Android 目标使用 NDK clang。
- Python 3。

```powershell
cd 'D:\研究方向\多模态\qingjian-mobile'
.\scripts\build_android.ps1
```

脚本以 cargo --locked 编译两种 ABI，再调用 aapt2/javac/d8/zipalign/apksigner 生成测试包。`D:\codex-mobile-build` 中的 junction 只是为不支持中文路径的 SDK 工具提供英文路径，实际文件仍留在原目录。其他位置可用 `-ToolchainDirectory` 和 `-AsciiBuildDirectory` 参数。

Debug 签名密钥留在本机工具链目录，源码交付包不含私钥。在其他机器重新生成测试密钥后，不能覆盖安装当前签名的 APK；测试者可卸载旧包再装，新安装会清除学习数据。

`android/` 另提供 Android Studio/Gradle 工程描述。打开时要先执行数据准备并生成 jniLibs；本次实际验证的是上述直接 SDK 构建脚本，未执行 Gradle 构建。

## 主机引擎测试

按本机配置设置 RUSTUP_HOME/CARGO_HOME/PATH 与 CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER，执行：

```powershell
cargo build --locked -p wordtrail-mobile
python tests/test_native.py
cargo fmt -p wordtrail-mobile --check
cargo clippy -p wordtrail-mobile --no-deps -- -D warnings
```

测试读取 `data/` 的完整官方词库。不会读写用户桌面输入法的学习文件。

安卓界面检查使用本机模拟器和独立窗口读取测试 APK：先运行 `scripts/build_android_probe.ps1`，再执行 `python tests/test_android.py`。脚本仅允许 emulator-* 目标，不会自动操作连接的真机。窗口读取器包含 FLAG_RETRIEVE_INTERACTIVE_WINDOWS，可以检索输入法窗口，不会停止词伴进程。

## Mac / iOS

安装 Xcode 并完成首次初始化，安装 Rust 1.96、Python 3、XcodeGen。不要把 Windows 的 toolchain.json 当作 Mac 配置。
本版 Swift 源码使用 Swift 5.9 语法，需 Xcode 15 或以上；工程语言模式仍为 Swift 5。

```bash
bash scripts/build_ios.sh
open ios/Wordtrail.xcodeproj
```

脚本生成 arm64 真机 + arm64/x86_64 模拟器的静态 XCFramework，以及 XcodeGen 工程。头文件模块名称 WordtrailCore，C 函数返回的字符串必须用 qjm_string_free 释放。Swift 扩展通过串行 DispatchQueue 调用。

当前工程最低 iOS 16，Swift 5，宿主 org.wordtrail.keyboarddemo，扩展 org.wordtrail.keyboarddemo.keyboard。正式安装请设置自己的唯一标识与签名团队。RequestsOpenAccess=false，不配置 App Group，语言选项放在键盘自己的 UserDefaults。

外观：两端包含 jade/lavender/night 三套同值配色。Android 设置页与键盘共享本机 settings 偏好；键盘 ◐ 在候选区显示主题选择条，选择后从当前候选快照重绘界面，保留引擎会话。避免使用会抢占宿主窗口焦点的 PopupMenu；换肤也不更换整个 InputView。两端换肤都只重绘候选，不重新写入未完成拼音，也不重复应用上一条 commit/delete。iOS 宿主与扩展各用自己的 UserDefaults；宿主按钮仅预览应用，键盘菜单选择键盘主题。源码由 Shared/WordtrailPalette.swift 同时加入两个目标。

需要在 Mac 上确认：Swift 编译、静态库链接、数据资源路径、扩展内存峰值、键盘显隐和文档切换、部分候选上屏后的剩余拼音、长按/地球键，以及 iPhone/iPad 布局。目前均不得视为已验证。

## 数据与来源

复核专四/专八/托福/雅思批次时，先运行 `python scripts/bootstrap_vocab_tools.py`，它会校验固定 SHA-256 后把 OpenCC Python 0.1.7 放入被忽略的 `build/vocab-tools/`。该工具只供构建审计中的繁简转换使用，不进入运行程序；来源与许可见 `vocabulary/data/OPENCC-PYTHON-ATTRIBUTION.md`。

`data/manifest.json` 固定记录实际字节及哈希。`prepare_data.py` 优先复用交付包中的数据，在本机也可复制已校验的官方 Windows 安装数据。缺失时从固定 data-v2 官方归档下载并核验归档 SHA-256，再只提取明确列出的文件。

原始青简提交固定为 f7abaefcb1a3aeaca5c01692941a64a7b1f43eb5（v0.1.4）。`vendor/qingjian` 未修改。新增层位于 native/android/ios/pronunciation/desktop/scripts/tests。desktop 是单独复制并增强的服务源码，vendor 原样保留。

`third-party/rust-ipa` 与 `.cargo/config.toml` 包含 Cargo.lock 对应的 registry 依赖，保留其源码和许可，不包含本机 SDK/JDK/NDK 二进制。

## 独立音标数据

`pronunciation-en.qj` 与四份官方数据独立。`prepare_pronunciation.py` 合并固定 ipa-dict 提交的 UK/US 数据，校验原始文件哈希，再由 Rust `pack-pronunciation` 编译为 QJ 容器。音标在 sense.text，地区在 sense.reading；没有 UK 时不会把 US 误标为 UK。`PronunciationDictionary` 复用 mmap/索引查询，对英文词条去首尾空格、转小写后精确匹配，不在线翻译或推测缺词发音。

源提交：43c3570eb3553bdd19fccd2bd0091534889af023。UK 为 GPL-3.0-only，US 为 MIT；原始文本、许可与哈希在 pronunciation/source/，生成信息在 data/pronunciation-manifest.json。保留上游全部发音变体，未做词性消歧或音频生成。

移动会话 JSON 新增可选 pronunciation 字段。安卓升级为 data-0.1.4-ipa1 数据目录，学习目录不变；iOS 资源脚本同步第五份 QJ。手机显示第一条英语释义的音标，标明对应单词；日语、西语不查英语音标。旧数据无音标文件时仍能输入。

## Windows 增强服务

`desktop/` 复用上游原服务，保持协议 7、TSF DLL 与用户配置不变。候选渲染时对英语各 sense.text 查独立音标并附加旁注；原译词和上屏行为不改动。音标文件路径为 EXE 同目录 data/pronunciation-en.qj。自定义 cosmic-text 固定上游指定 Git 提交，连同 registry 依赖完整保存在 third-party/rust-ipa。

运行 `scripts/build_desktop.ps1` 编译。独立测试通过 WORDTRAIL_TEST_PIPE 及 APPDATA/LOCALAPPDATA 临时目录运行，不占用正在使用的官方服务管道。`scripts/package_desktop.py` 只用于首次打包前读取尚未替换的原版 EXE 哈希；安装脚本核对支持版本、保留原版备份并支持恢复。补丁 EXE 未签名，UIAccess=false，不宣称管理员宿主与特殊系统界面已验证。
## 安卓系统语音输入（0.1.3）

`SpeechInput.java` 封装短时 `SpeechRecognizer` 会话。API 31+ 优先 `createOnDeviceSpeechRecognizer`，设备服务或当前语言不可用时，只有用户允许系统服务后才使用 `createSpeechRecognizer`。系统服务路径明确显示可能联网；`EXTRA_PREFER_OFFLINE` 不能当成离线保证。通过 `<queries>` 声明识别服务可见性，新增 `RECORD_AUDIO`，未新增 INTERNET。

`SpeechPermissionActivity` 负责可见的运行时权限申请，不自动开始录音。键盘麦克风替换候选区为固定 72dp 的预览 / 完成 / 取消区。临时结果不进入编辑器，最终结果经 `InputConnection.commitText` 插入一次。取消、隐藏键盘、换输入框及销毁会使会话 token 失效并 cancel / destroy；最大等待 45 秒，结束后的结果等待 10 秒。密码和数字框禁用语音，未完成拼音保留并提示先选词。

`tests/speech-service/` 是独立测试 APK，用合成回调检查真实 RecognitionService Binder、授权 UI 和输入框安全，不进入生产 APK。运行 `scripts/build_speech_test.ps1` 与 `tests/test_speech_input.py`；仅使用明确指定的模拟器并恢复识别服务设置。该测试不验证真实录音转写准确率，真机还需要验证语言包、麦克风、系统服务和网络条件。

## 安卓紧凑候选布局（0.1.5）

候选模型仍每页返回 9 条，不改原词库、释义或音标数据。Android 在实际测量宽度下，以约 70dp 的候选目标宽度计算一屏数量，上限 9；候选统一 46dp 高，两个文本行。无候选时 HorizontalScrollView 设为 GONE，模式提示移动到已有工具栏。主题选择显式展开候选容器；退出语音按当前候选状态恢复容器，避免空闲留白再次出现。完整释义/多音标继续在独立滚动面板展示。

独立语音由 `LocalSpeechInput` 使用 AudioRecord 采集 16kHz 单声道 PCM16，最多 30 秒，仅保存在内存。推理在独立单线程执行器运行，约每 4 秒尝试预览，停止录音后取得最终结果。`LocalVoiceBridge` 通过 C API 调用固定 sherpa-onnx 1.13.8 / SenseVoice int8；SDK 库和新增 JNI 均验证 16 KB 对齐。模型及 tokens 首次复制到应用私有目录并核对 SHA-256，后续校验标记和长度；不含运行时网络下载或录音文件。

每次语音有独立 Session，取消会使其回调失效。IME 保留额外的 speechToken 和 editor epoch 校验。密码/数字字段禁用麦克风；未完成拼音不启动录音。识别过程不持有 InputConnection，只有有效最终回调在主线程重新获取当前连接并提交。局部预览绝不上屏，取消也不会触发最终提交。

原系统语音作为可选方式保留。没有公开 RecognitionService 时，系统设置页不再提供空服务列表，也不跳入可能映射为数字助理的系统设置页。vivo 用户截图的 null 默认服务和空公开服务列表是该设备不能使用原系统路径的依据；默认本机方式不依赖它。

原生音频验证采用单独签名的 instrumentation 测试 APK，加载最终应用中的真实原生库和模型，对官方中文/英文 WAV 执行解码。麦克风 UI 测试使用真实 AudioRecord，模拟器输入为静音，因此只证明授权、取消、时限和编辑器安全流程，不代表用户设备的麦克风识别准确率。测试代码与音频不进入交付 APK。

## 安卓系统语音兼容修正（0.1.4）

`SpeechServices` 查询公开、启用且声明 BIND_SPEECH_RECOGNITION_SERVICE 的服务；优先使用用户指定的有效组件，再使用有效系统默认组件。仅在自动模式、默认失效且恰有一个服务时恢复选择，多个服务要求用户选择。手动服务失效不会静默转交音频。系统服务使用 `createSpeechRecognizer(context, component)` 明确绑定，设备离线服务仍使用标准设备接口。

`SpeechSettingsActivity` 是非导出设置页，允许服务选择、离线优先开关、权限查看及主动复制诊断。诊断只读取设备信息、服务组件、权限和最近错误，不读取编辑器内容或音频。失败区保持 72dp，显示错误编号与服务，并提供设置、其他输入法及返回入口；会话先结束并失效，不在失败后自行重录。旧的双层会话 token、取消、重复和迟到结果保护继续保留。苹果和桌面未新增语音能力。

## 0.1.6 自动分级、语音完成与触屏

`native/src/vocabulary.rs` 使用 LazyLock 一次载入上游8,845条原始等级表，生成每条英文 sense 的 VocabularyLevel。大小写及首尾空白归一化，精确匹配整条译词；未收录为 null，日/西语为空数组，不修改 .qj 数据。等级表编译进共享 Rust 引擎。Android 默认显示第一条译词小标签，独立持久化开关；详情显示各译词等级。iOS 使用可选解码字段，在0.1.2界面基础上显示标签及详情，未编译验证。

语音采用帧能量截取和 Silero VAD，两条预览/完成路径共享处理。本机 VAD 在推理执行器运行，对分析副本归一化以保留轻声，ASR接收原始音量及短上下文；每个快照重置检测状态，不跨录音混用。VAD固定SHA及许可保留在 prepare_voice.py / provenance.json，约0.64MB，首次验证复制。Session.lastPreview 仅缓存本会话模型实际非空文字；最终为空或解码异常时使用缓存。正常停止引起的麦克风读取中断不再改写 finish；取消与输入框 token 检查仍生效。

快速触屏测试证明仅修改按下响应不足以避免首次候选展开时漏字。最终 onConfigureWindow 固定透明输入窗口尺寸，setInputView 锚定框架 parentPanel 到底部；onComputeInsets 根据实际 root 区域报告占用空间和可触摸区域，上方应用仍可点击。实际键盘仍随候选/详情变化，无空白占位。[Android Insets 官方定义](https://developer.android.com/reference/android/inputmethodservice/InputMethodService.Insets)。需保持非全屏编辑模式；onEvaluateFullscreenMode 返回 false。TypingKey 仅用于字母/数字/标点/空格，DOWN执行一次 performClick，UP/CANCEL只复位，TalkBack点击继续调用同一逻辑；按键无需缩放动画。候选保留原触摸/长按/滑动行为。

`tests/test_rapid_typing.py` 通过独立 WindowProbe 在预先测量的真实屏幕坐标注入定时DOWN/UP，并核对整个编辑框，不用逐字ADB命令的延迟掩盖丢键。语音完成回归通过独立 instrumentation 执行生产 Java 与真实 C API：轻声长静音、真实预览后空最终、新会话静音、白噪声、取消；夹具PCM只代替麦克风，不代替识别结果。完整说明和实际限制见0.1.6测试报告。
